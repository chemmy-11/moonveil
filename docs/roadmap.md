## 三、游戏内容方向（规划中，待对齐）

> 定位：把情感陪伴从「被动应答」升级为「有内容的互动」，本质是给聊天加叙事层/玩法层，不改底层架构。

### 候选模块（可组合）

**G1 · 关系阶段系统**
- 三位女友各自有「关系温度/阶段」（初识 → 熟悉 → 依赖），由对话频率 + 本地记忆体系驱动
- 阶段影响开场白、称呼、互动分寸；公开版上限到「稳定陪伴」，无成人内容
- 依赖：本地记忆体系 + 本地状态机

**G2 · 随机生活事件**
- 女友主动「发消息」：分享日常、邀约、小情绪（模拟推送）
- 事件有触发条件（时间段、记忆关联、话题）与稀有度
- 桌面版落地为「离线回来看到新消息」；移动端后续可接真推送

**G3 · 记忆驱动剧情回调**
- 基于本地记忆体系在合适时机主动提旧事（「你上次说想去的店，我路过了」）
- 纪念日/重要事件触发的特殊对话

**G4 · 成就与收集**
- 里程碑（连续聊天 N 天、共同回忆 N 条、解锁某事件）
- 收集图鉴：女友的「小癖好」、共同回忆、事件卡

### 建议路线

1. **G1 关系阶段 + G3 记忆回调** 先行——最能强化「真实感/沉浸度」这一项目目标，且直接复用已建好的记忆基础设施
2. **G2 随机事件** 次之——需要事件内容库与调度，工作量中等
3. **G4 成就收集** 作为锦上添花，提升留存与可展示性

## 四、工程债与技术注意

- [ ] 字体子集仅覆盖 GB2312 一级常用字 + ASCII + 常用标点（脚本已入库 `scripts/subset-fonts.py`）——生僻字缺字时需扩字面重跑子集
- [ ] 公开仓库约束：无成人内容、素材版权可商用（见 UI 优化计划书第四节）

## 五、发布规范

- 版本三处同步一条命令：`bash scripts/bump-version.sh [版本号]`（js/version.js 唯一源头 → build.sh 注入 index.html 缓存号 → build.gradle versionName/versionCode，issue #25；不带参数则 patch +1）
- 版本线说明：2026-09 重开为 `0.x.y` 线（旧 1.x 线止于 v1.8.1 / versionCode 181）；versionCode 规则 `(major+1)×1000 + minor×10 + patch`（0.2.6 ↔ 1026），必须严格递增——OTA 检查更新依赖它递增，重开版本线时**必须核对 versionCode 高于旧线**（bump 脚本已内置该校验）
- 发版后同步 `chemmy-11/moonveil-updates` 仓库（APK + latest.json）供 App 检查更新
- 提交信息遵循 `<动词>: <改了什么>`；改 personas 需同步 `js/data.js`
- Issue / PR 提报规范（仓库基线、标题与正文模板、合并前自查清单、隐私红线）见 `docs/issue-pr-conventions.md`
