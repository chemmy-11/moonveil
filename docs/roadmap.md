## 三、游戏内容方向（规划中，待对齐）

> 定位：把情感陪伴从「被动应答」升级为「有内容的互动」，本质是给聊天加叙事层/玩法层，不改底层架构。

### 候选模块（可组合）

**G1 · 关系阶段系统**
- 三位女友各自有「关系温度/阶段」（初识 → 熟悉 → 依赖），由对话频率 + EbbingFlow 记忆驱动
- 阶段影响开场白、称呼、互动分寸；公开版上限到「稳定陪伴」，无成人内容
- 依赖：EbbingFlow 记忆 + 本地状态机

**G2 · 随机生活事件**
- 女友主动「发消息」：分享日常、邀约、小情绪（模拟推送）
- 事件有触发条件（时间段、记忆关联、话题）与稀有度
- 桌面版落地为「离线回来看到新消息」；移动端后续可接真推送

**G3 · 记忆驱动剧情回调**
- 基于 EbbingFlow 记忆在合适时机主动提旧事（「你上次说想去的店，我路过了」）
- 纪念日/重要事件触发的特殊对话

**G4 · 成就与收集**
- 里程碑（连续聊天 N 天、共同回忆 N 条、解锁某事件）
- 收集图鉴：女友的「小癖好」、共同回忆、事件卡

### 建议路线

1. **G1 关系阶段 + G3 记忆回调** 先行——最能强化「真实感/沉浸度」这一项目目标，且直接复用已建好的记忆基础设施
2. **G2 随机事件** 次之——需要事件内容库与调度，工作量中等
3. **G4 成就收集** 作为锦上添花，提升留存与可展示性

## 四、工程债与技术注意

- [ ] EbbingFlow 侧改动（CORS/loopback 放行/bind-mount）在本地副本 `L:\ebbingflow`，未纳入版本控制；若长期依赖需考虑 fork 或补丁管理
- [ ] 字体子集脚本未入库——扩字面覆盖时需重建子集（当前 1164 字）
- [ ] EbbingFlow 数据卷残留测试数据（`docker compose down -v` 可重置）
- [ ] 公开仓库约束：无成人内容、素材版权可商用（见 UI 优化计划书第四节）
- [ ] 移动端记忆后端需公网部署（当前仅桌面 localhost）

## 五、发布规范

- 版本三处同步：`js/version.js`（唯一源头）→ build.sh 自动注入 index.html → `build.gradle` versionCode/Name 手动同步
- 发版后同步 `chemmy-11/moonveil-updates` 仓库（APK + latest.json）供 App 检查更新
- 提交信息遵循 `<动词>: <改了什么>`；改 personas 需同步 `js/data.js`
